# Daily operations

## Start of day

Ask the orchestrator for:

- open initiatives and current status
- blocked work
- failed CI checks
- pull requests requiring approval
- staging incidents
- security or dependency alerts

## Starting work

Every request should identify:

- desired business outcome
- affected product
- urgency
- constraints or required behavior

The product and requirements agents should convert incomplete requests into traceable issues before implementation begins.

## Ending work

The orchestrator should provide:

- changes completed
- tests and reviews performed
- preview or staging links
- decisions requiring human approval
- unresolved risks
- estimated model and infrastructure usage where available
