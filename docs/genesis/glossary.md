# Genesis Glossary

**Status:** Canonical terminology
**Version:** 0.1.0

| Term | Definition |
|---|---|
| Agent | A software principal performing a delegated role through tools and providers |
| Application | A user or system interaction surface consuming platform capabilities |
| Authority | An explicit grant to decide, approve, access, spend, direct, or act within limits |
| Binding | Approved and required for the stated scope |
| Budget | An authorized financial constraint with period, categories, limits, and approval rules |
| Capability | The ability to produce a defined outcome under stated conditions |
| Capability contract | A provider-independent definition of operations, behavior, and evidence for a capability |
| Canonical | The governing source within an identified scope and authority level |
| Conformance | Evidence that an implementation satisfies a declared contract version |
| Current | Implemented and validated in the repository or stated environment |
| Decision record | Provenance for a material choice, alternatives, authority, cost, risk, and outcome |
| Deferred | Intentionally outside the current delivery scope |
| Domain | A cohesive area of business rules, language, ownership, and state |
| Evidence | A verifiable artifact supporting a claim |
| Executive Core / Mayor | Proposed policy and coordination layer that turns authorized intent into governed work |
| Genesis | The first budget-aware, end-to-end Devsembly reference implementation |
| Human authority | A person or authorized human body holding final governance and risk authority |
| Idempotency | The property that safely repeated requests do not create unintended additional effects |
| Kernel | Proposed logical platform boundary for capabilities, providers, policy, events, workflow, memory, configuration, and observability |
| Knowledge object | Governed information with source, version, confidence, access, and retention |
| MemoryOS | Proposed governed memory capability; not a single database or model context |
| Organizational Genome | Canonical model for organization structure, roles, capabilities, authority, policy, work, knowledge, and evidence |
| Plugin | A packaged, permissioned extension declaring capabilities, providers, contracts, and lifecycle |
| Principal | A human, agent, service, or provider identity subject to policy |
| Proposed | Designed for review but not yet binding |
| Provider | A replaceable implementation of one or more capabilities |
| Repository | A domain-oriented collection interface, distinct from a source-code repository when used in persistence context |
| Source-control provider | Provider for repositories, commits, branches, pull requests, reviews, and releases |
| System of evidence | Authoritative source for evidence it produces, without owning unrelated domain policy |
| Tenant overlay | Tenant-specific extension or selection that does not mutate canonical reusable records |
| Unit of Work | An application transaction boundary coordinating repositories, commit, rollback, and outbox events |
| Workflow | Versioned executable coordination of tasks, decisions, events, timeouts, and escalation |
